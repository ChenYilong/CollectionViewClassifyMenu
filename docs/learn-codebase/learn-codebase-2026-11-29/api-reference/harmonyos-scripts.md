# harmonyos: scripts

Generated by script from the source at 03707ba2. Comments are copied from the code ([CN] lines left out), so a stale source comment is stale here too. Pattern-based: some declarations can be missing or truncated to their first line.

## harmony/scripts/accessibility-check.py

Fails when a HarmonyOS component a screen reader meets has neither a label nor an explicit choice.
Checks the library (classifymenu) and the example (entry): every Image, TextInput, Toggle, Slider, Search, Canvas,
Checkbox and LoadingProgress has `accessibilityText`, `accessibilityLevel('no')` (decorative) or
`accessibilityGroup` in its attribute chain. Usage: harmony/scripts/accessibility-check.py

## harmony/scripts/build.sh

Installs the ohpm dependencies and builds the HarmonyOS project (the classifymenu HAR and the entry HAP).
Usage: harmony/scripts/build.sh [hvigor task, default: assembleHap]. DEVECO: DevEco Studio's folder (macOS: the
app's Contents; Windows: C:/Program Files/Huawei/DevEco Studio, the default when it exists).

## harmony/scripts/check-native-strings.py

Checks the native HarmonyOS string resources (resources/<language>/element/string.json).
- Every language folder of a module has the same names as its `base` folder.
- The tab titles copied from CYLTabBarController's HarmonyOS example (`tab_home`, `tab_nearby`, `tab_messages`,
`tab_me`) match the iOS example strings: `en_US` the English, `zh_CN` the key, `zh_TW` the Traditional Chinese.
Usage: harmony/scripts/check-native-strings.py

## harmony/scripts/export-example-strings.py

Writes harmony/entry/src/main/ets/data/CYLExampleStrings.ets: the example's strings
(Example/CYLMenuExample/CYLMenuExample.bundle/*.lproj/Localizable.strings) for CYLExampleLocalizedString, and the
search history and discover demo's data of each language (*.lproj/search-discover.json), as iOS reads them.
export-example-strings.py           write the module
export-example-strings.py --check   exit 1 when it is out of date
The keys are the Simplified Chinese text, as on iOS; zh-Hans therefore needs no table of its own.

## harmony/scripts/harmony_parity.py

Write docs/harmony.md: the iOS public API and the iOS example's demos, each with its HarmonyOS counterpart.
harmony_parity.py            write docs/harmony.md from the Swift core and harmony/parity-map.json
harmony_parity.py --check    exit 1 when docs/harmony.md is out of date
harmony_parity.py --list     print every public iOS symbol, one per line
harmony_parity.py --todo     print the TODO rows (API first, then demos)
The API is every `public` / `open` declaration of the pod's Swift sources (CollectionViewClassifyMenu.podspec:
source_files minus exclude_files), overrides of UIKit members left out: types, properties, methods (with their
argument labels), initializers, enum cases, static members. The demos are the screens of the iOS example
(Example/CYLMenuExample), listed in parity-map.json "demos" in the order of the example.
parity-map.json: {"api": {"<symbol>": "<ArkTS counterpart>"}, "demos": [{"ios": ..., "shows": ..., "harmony": ...}]}.
A row without a counterpart is TODO. The score is aligned rows / all rows of both tables, out of 100.

## harmony/scripts/parity_map.py

Adds rows to harmony/parity-map.json and regenerates docs/harmony.md.
parity_map.py api '<iOS symbol>=<ArkTS>' ...       map API rows (an unknown symbol is an error)
parity_map.py demo '<iOS demo>=<HarmonyOS page>'   map a demo row
parity_map.py history '<text>'                     append a line to the score history (the score is added)

## harmony/scripts/screenshots.sh

Screenshots of every demo of the HarmonyOS example on the running emulator (docs/harmony-verification.md rows B,
E3 and F2): builds and installs the example, opens each screen with the launch options of CYLLaunchOptions
(cylScreen, cylScreenParam, cylLanguage, cylColorMode), and saves docs/assets/harmonyos-<name>.jpeg.
Usage: harmony/scripts/screenshots.sh [name ...] (default: all). DEVECO: DevEco Studio's folder.

## harmony/scripts/ui-test.sh

Builds the example and its instrumented test (entry/src/ohosTest), installs both on the running emulator and runs
the UI tests. Usage: scripts/ui-test.sh [project dir, default: harmony/]. Needs DevEco Studio and a booted emulator.

## harmony/scripts/unit-test.sh

Runs the local unit tests (entry/src/test) on this computer, without a device, and prints the result.
Usage: harmony/scripts/unit-test.sh. DEVECO: DevEco Studio's folder (the Windows default when it exists).
