- `export class CYLLifecycleBridge<T extends Object>` (L25)
  Feeds a `LifecycleController` from the real ArkUI window events and the ability callbacks.
  The page forwards its own callbacks, one line each:
  ```ts
  @Component struct Page {
    private bridge: CYLLifecycleBridge<Object> = new CYLLifecycleBridge<Object>(this);
    aboutToAppear() { this.bridge.aboutToAppear(); }
    onPageShow() { this.bridge.onPageShow(); }
    onPageHide() { this.bridge.onPageHide(); }
    aboutToDisappear() { this.bridge.aboutToDisappear(); }
    build() { Column() {}.onAreaChange((o: Area, n: Area) => this.bridge.onAreaChange(o, n)) }
  }
  ```
  `attachWindow(win)` subscribes the window size and avoid-area events (removed in
  `aboutToDisappear`); the ability forwards `onConfigurationUpdate` (color mode) and
  `onMemoryLevel`. Add blocks on `bridge.controller.registry`, before `aboutToAppear` for the
  `viewDidLoad` blocks.

- `export class LifecycleCenter` (L33)
  Global observers: one block that observes an event on every object, for
  behavior that must not know its owners ("pause every animation while the user
  scrolls"). Per-owner blocks run first, then the global ones, each group in
  identifier order. Global observers never receive teardown events: the owner is
  going away. A key replaces the observer added before under it.

- `static get isUserScrolling(): boolean` (L39)
  True while any observed scroll source is dragging or decelerating.

- `static whileUserScrolls(pause: () => void, resume: () => void, options: KeyOptions = {}): () => void` (L74)
  The ready-made version of "pause every animation while the user scrolls, resume afterwards": `pause` runs when any observed scroll
  source starts to be dragged, `resume` when it stopped for good. Returns a function that removes both observers. The two
  observers use the keys `<key>.pause` and `<key>.resume` (default key `cyl.scroll`), so calling it again replaces the earlier pair.

## harmony/cyldeallocblockexecutor/src/main/ets/controller.ts

- `export class LifecycleController<T extends object>` (L35)
  Fires the lifecycle events of an ArkUI page or component from the callbacks
  ArkUI already calls (push model, like the Android controller): the page's
  handlers forward to this controller, so no event needs code in the handler
  itself beyond one call.
  Mapping (iOS event: ArkUI source):
  - `willMoveToParent`, `viewDidLoad`, `didMoveToParent`: `aboutToAppear()`;
  - `viewWillAppear`, `viewIsAppearing`, `viewDidAppear`: `onPageShow()`
    (ArkUI has no separate transition end, so the three fire back to back,
    `animated` false);
  - `viewWillDisappear`, `viewDidDisappear`: `onPageHide()`;
  - `viewDidLayoutSubviews`: `onAreaChange(old, new)` of the root component;
    `viewWillTransition`: the same call when the size changed;
  - `viewSafeAreaInsetsDidChange`: `avoidAreaChanged(insets)` (window avoid
    areas, system bars and cutout);
  - `traitCollectionDidChange`: `colorModeChanged(mode)`;
  - `didReceiveMemoryWarning`: `memoryLevel(level)` from `UIAbility.onMemoryLevel`;
  - teardown blocks: `aboutToDisappear()`.
  - `viewWillLayoutSubviews`, `viewLayoutMarginsDidChange`: no source.
  - design v5: `windowAttached()` / `windowDetached()` (`onAttach` / `onDetach`) fire the window moves;
    `visibleAreaChanged(visible)` (`onVisibleAreaChange`) and `onPageShow` / `onPageHide` fire
    `didEnterScreen` / `didLeaveScreen` on transitions; `scrollStarted()` / `scrollStopped()`
    (`onScrollStart` / `onScrollStop`) fire the scroll events (ArkUI has no drag-end event, so a stop
    is a drag end without deceleration and the end of scrolling).

- `export class LifecycleRegistry` (L50)
  One registry per owner: the lifecycle blocks and the teardown blocks.
  The iOS rules (see `docs/Lifecycle-Callbacks.md`): one identifier counter for
  every block; blocks run in identifier order from a snapshot, so a block can
  add or cancel blocks; adding with a key replaces the block added before under
  that key (the new block starts unfired; keys are separate for lifecycle and
  teardown blocks); keyed blocks belong to their key holder: cancel-all and
  re-arm by event skip them. No lock: JavaScript runs one thread.

- `static of(owner: object): LifecycleRegistry` (L52)
  The registry of `owner`, created on first use.

- `onRegister: ((event: LifecycleEvent) => void) | undefined;` (L69)
  Called when a block is added for `event` (the controller attaches its sources lazily).

- `hookInstalled = false;` (L72)
  The controller sets this once its automatic hooks fire `beforeSuper` / `afterSuper`.

- `cancelLifecycleCallback(target: { identifier: number } | { key: string }): boolean` (L123)
  Cancels one block by `identifier` or by `key`; true when one was removed.

- `postLifecycleEvent(name: string, userInfo?: Record<string, unknown>): void` (L148)
  Runs the blocks of the custom event `name` (the owner's, then the global observers'), in identifier order.

- `forwardLifecycleEvents(target: LifecycleRegistry, events?: readonly LifecycleEvent[]): void` (L180)
  Forwards the events fired on this owner to `target`'s registry (all events, or the given set), as an object that is
  not a view gets the events of the view that shows it. The target is held weakly; forwarding to the same target again
  replaces the earlier forward. Posted custom events are forwarded too.

- `cancelAllLifecycleCallbacks(event: LifecycleEvent, timing?: LifecycleTiming): void` (L199)

- `rearmLifecycleCallbacks(event: LifecycleEvent, timing?: LifecycleTiming): void` (L204)

- `rearmLifecycleCallback(key: string): void` (L213)

- `cancelAllDeallocCallbacks(): void` (L244)
  Cancels the teardown blocks that have no key.

- `runDealloc(): void` (L261)

- `setManualLifecycleDispatch(` (L277)
  Declares that the owner dispatches `events` itself, for `timings` (all by default).

- `isAutomatic(event: LifecycleEvent, timing: LifecycleTiming): boolean` (L295)

  Fires the blocks of one (event, timing) by hand. The event must be declared manual first.

- `performLifecycle(` (L320)
  Runs `callSuper`, then `body`, with the timings around them. With the
  controller's hook the automatic timings come from the hook; this method
  adds `end` after `body`, at the outermost level only and not when `end` is
  declared manual. For an owner without a hook all three timings fire from
  the outermost call.
