# HarmonyOS port

## Rule

All code of this project, the HarmonyOS code included, supports visual accessibility and screen readers, and
internationalization and localization with localization files. If something does not, add the support first. In
automated UI tests, locate controls through these features first (the localized accessibility label, then the
accessibility description, then an id), to tap, to drive complex flows and to chain actions. Source: AGENTS.md
"HarmonyOS: accessibility, localization and accessibility-first UI tests".

## Fix issues in the core first

- The core is the code published to a package registry: the CocoaPods pod / Swift package, the Maven / Gradle
  libraries (`android/merged/library`, `android/AndroidTagView/androidtagview`), the npm package
  `react-native-cyl-tag-list` (not its examples), the pub.dev plugins (not their `example/`), the ohpm HAR
  `harmony/classifymenu` (not `harmony/entry`) and the mini program packages. Everything else is the example layer.
- Fix every issue or bug in the core first, even one seen only in an example screenshot, so that every app using the
  library and every similar case is fixed. Look for the core cause (a default, a missing option, a layout or
  measurement rule, a missing localization or accessibility hook, a color that ignores the color mode) before
  touching the example.
- An example-layer fix is the worst option: only for a defect that really is in example code or data (a demo string,
  a demo page's own layout, a screenshot script), or when the core cannot fix it.
- When a core defect cannot be fixed in the core: ask the user first and say why (a third-party bug, a platform
  limitation, an API kept for compatibility).
- Record every example-layer fix in `docs/example-layer-fixes.md` (issue, files, why not in the core) and mention it in
  the issue's progress-table row. Full rule: AGENTS.md "Fix issues in the core first".

## Bugs: record, screenshot, fix upstream

- Bugs (AGENTS.md "Bugs: record, screenshot, fix in CYLTabBarController's animated item"): record first, then screenshot, then fix; animation and icon + title bugs are fixed in CYLTabBarController's animated item component, not in the examples; a demo that needs more gets a new component API from CYLTabBarController.

## Accessibility

- `accessibilityText` (localized) on every control; `accessibilityDescription` when it helps;
  `CYLAccessibilitySelectedModifier` for the selected state (API 13+, the library targets API 12).
- A row or button of several views: `accessibilityGroup(true)` and one label. An icon beside its label:
  `accessibilityLevel('no')`. A text field: labeled like its placeholder. Sizes in `fp`.
- `harmony/scripts/accessibility-check.py` must print OK.

## Localization

- Example: `CYLExampleLocalizedString(key)` (keys are the iOS example's Simplified Chinese strings), generated by
  `harmony/scripts/export-example-strings.py`; core: `CYLMenuLocalizedString`.
- Native resources (`resources/{base,en_US,zh_CN,zh_TW}/element/string.json`): app name, ability label, and the tab
  titles copied from CYLTabBarController's HarmonyOS example (`CrossPlatform/harmonyos-cyltabbar`) that this
  project uses. `harmony/scripts/check-native-strings.py` must print OK.
- Never compare translated text in code; compare keys or flags.

## UI tests (emulator)

- `cylTapAccessible(driver, CYLExampleLocalizedString('<key>'), '<fallback id>')` and `cylFindAccessible` in
  `harmony/entry/src/ohosTest/ets/test/TestSupport.ets`; `cylTap(driver, id)` only for controls without a label.
- One test file per feature; run with `harmony/scripts/ui-test.sh` on a booted emulator.

## Commands

```sh
harmony/scripts/build.sh                 # HAR + HAP
harmony/scripts/unit-test.sh             # local unit tests on the computer, no device
harmony/scripts/svga-decoder-test.sh     # SVGA decoder against zlib
harmony/scripts/accessibility-check.py   # labels on every image, input and control
harmony/scripts/check-native-strings.py  # native string resources
harmony/scripts/ui-test.sh               # UI tests on the emulator
harmony/scripts/screenshots.sh           # every demo, English, Traditional Chinese, dark mode
```
